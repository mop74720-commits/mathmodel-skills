# Numerical Robustness & Reproducibility

## 数值稳健性

1. 对乘积很小/很大的概率、似然和组合量优先使用 log-domain；求和指数项使用稳定的 log-sum-exp 形式。
2. 当变量跨多个数量级时先缩放或无量纲化，再判断优化器/积分器是否真的失效。
3. 对线性系统、回归或局部二次问题检查条件性；病态时优先正规化、重新参数化、稳定分解或提高精度，而不是盲目增加迭代次数。
4. solver 必须匹配结构：连续/离散、凸/非凸、稀疏/稠密、ODE/PDE stiffness、约束类型等。
5. 随机算法固定 seed；非凸或启发式算法保留 multi-start/多 seed 结果并报告分布，不只报最佳一次。
6. 记录停止准则、容差、残差、约束违反量和迭代状态；“程序退出码 0”不等于数学收敛。
7. 先跑小规模 sanity case，再扩到全数据；大规模失败时保留确定性的降级路径。
8. 至少检查边界条件、守恒/单调/非负等结构性不变量（若模型应满足）。

任何条件数、超时或容差数值只能作为可配置诊断阈值，不能冒充普适数学定理。

## 复现合同

关键运行至少绑定：
- 命令与工作目录；
- seed；
- 输入文件哈希；
- 核心产物哈希；
- Python/solver/关键依赖版本；
- Git commit（若存在）；
- 时间戳与运行状态。

使用 `tools/reproducibility` 创建/验证 manifest。不得把完整环境变量、token 或密钥写入 manifest。
