# Paper Quality Contract

本合同约束“如何把已经验证的 Competition Repo 证据压缩成高质量竞赛论文”。它不是比赛阶段，也不是固定流水线；只有当前论文问题与这些能力相关时才加载。

## 1. 两个不同目标必须分开

### Scientific / Compliance Correctness
回答：
- 数学是否正确；
- 结果是否有证据；
- 官方硬约束是否满足；
- 提交物是否完整。

### Editorial / Judge Quality
回答：
- 评委能否快速找到每问答案；
- 核心模型是否讲清“为什么这样建”；
- 关键结果是否通过表图和文字形成闭环；
- 正文是否把有限注意力花在最重要的信息上。

前者 PASS 不自动推出后者优秀；后者也不能掩盖前者 FAIL。

## 2. Repo completeness != Paper completeness

Competition Repo 应尽量完整保存：失败 Run、审计、provenance、实验细节、AI 使用记录、复现环境、完整代码。

论文正文应选择性表达：
- 题目真正要求的答案；
- 必要模型与关键推导；
- 决定结论的结果和验证；
- 对结果有解释力的图表；
- 必要限制。

原始日志、长 provenance、内部治理记录、完整调试历史、重复推导、代码清单等默认不进入正文。只有官方规则明确要求或其本身影响科学解释时才进入论文/附录。

## 3. Main text / Appendix / Support 三层隔离

### Main text
服务阅卷与科学论证。要求连贯、紧凑、可快速扫读。

### Appendix
承载官方要求必须随论文出现、但不适合占据正文叙事带宽的内容，例如完整源程序、扩展推导、额外结果。附录很长不等于正文可以失去编辑质量。

### Support package
承载可复现资产、完整代码、环境、AI 详情、原始/派生数据说明和其他支撑材料，具体服从当届官方规则。

禁止为了“合规更安全”把审计报告、AI 历史、仓库路径、Run ledger 或大段源代码直接塞进正文；若官方要求完整代码进入论文，则放入明确隔离的附录，并单独评价正文质量。

## 4. Claim-first synthesis

每个核心子问题形成尽可能短的闭环：

`问题/决策 -> 模型机制 -> 关键结果 -> 证据表图 -> 解释/意义 -> 必要边界`

不是每问都必须机械使用同样小节，也不规定固定图数、公式数或页数。

## 5. Figure/Table storytelling

优先把高价值信息做成读者容易比较的表图，而不是埋在长段落。

一个表图应回答一个清晰问题。正文必须说明它支持什么 claim；图注负责对象、场景、指标、单位和必要统计口径，而不是重复正文。

避免：
- 只有装饰意义的流程图；
- 把能一句话说清的两三个数字画成复杂图；
- 多张图重复同一 claim；
- 重要比较只存在于文本中、无法快速扫描。

## 6. Editorial compression

优先压缩或迁移：
- 题目大段重述；
- 算法百科；
- 重复假设/符号/共享模型；
- 与结论无关的中间实验；
- 逐行朗读表格；
- 重复公式；
- 内部 QA / audit / provenance 语言；
- 实现日志和调试过程。

不得压缩掉：
- 影响可行域/结论的题面硬约束；
- 模型关键机制；
- 关键变量与单位；
- 使强 claim 成立的验证；
- 对结论有实质影响的限制。

## 7. Judge scan path

Judge Review 默认模拟有限注意力下的扫读：
1. 摘要：能否迅速知道每问方法和最终答案；
2. 问题分析/模型总览：能否理解整体路线和依赖；
3. 每问开头/结尾：能否快速找到该问直接答案；
4. 关键表图：是否能独立读出最重要比较；
5. 模型与推导：是否足够支撑结果而不过载；
6. 结论/评价：是否与前文一致且不过度宣称。

输出“scan friction”而不是虚构评委打分。

## 8. Rendered-page quality

最终质量判断必须查看实际 PDF/渲染页，而不是只看 Markdown/DOCX/LaTeX 源。

重点看：
- 一页是否只有零散公式和大片无意义空白；
- 表图是否跨页/缩得过小；
- 标题是否孤立在页尾；
- 公式是否把解释文字挤散；
- 正文视觉节奏是否明显被长附录或合规插补破坏；
- 主正文结束点与附录开始点是否明确。

不设通用“每页文字比例”或固定页数阈值；依据实际阅读效果与官方规则判断。

## 9. Compliance overlay principle

合规修复默认采用“最小必要修改”：
- 不改变科学事实；
- 不把治理文字扩写成正文主线；
- 不因加入附录而重写已经成熟的正文结构，除非排版确实受到影响；
- 若一次合规修改显著恶化正文，应回到稳定正文版本重新设计 overlay，而不是继续堆补丁。

## 10. Quality gate semantics

- 数学/证据错误：由对应 scientific QA FAIL。
- 官方硬约束失败：由 rules/final-review FAIL。
- 论文可读性差：Judge Review / editorial skill 给 WARN/FAIL（仅针对论文质量），不冒充科学错误。
- 是否继续花时间美化仍由 Coach 决定。
