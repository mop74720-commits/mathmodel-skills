# system-dynamics

## Trigger

- 事件：`ALGO_SYSTEM_DYNAMICS`。
- 当问题以库存、流量、反馈回路、时滞和政策情景为核心，且重点是系统级长期演化而非个体微观行为时调用。

## Scope

覆盖系统动力学/stock-flow 建模。若能直接写清晰 ODE，也可与 `ALGO_ODE_DYNAMICS` 联用；系统动力学的价值在反馈结构和政策情景，不在软件名。

## Inputs

- 关键库存与流量变量
- 因果关系与反馈方向
- 时间尺度和延迟
- 参数/初值来源
- 需要比较的政策或情景

## Procedure

1. 先画因果回路，区分强化回路与平衡回路，避免把相关关系直接写成因果。
2. 将回路落到 stock-flow 方程，所有库存变化率必须由流入减流出构成。
3. 做单位/量纲检查，确保每个流量与库存的时间维度一致。
4. 识别延迟、饱和、容量和非线性函数；函数形状需要数据、机制或情景假设支持。
5. 找平衡点/极端情形，检查模型在零输入、饱和、长期稳态等边界是否合理。
6. 数值模拟时使用适合的时间步长并做步长收敛；如方程刚性或复杂，转 ODE 数值检查。
7. 政策情景只改变明确可控参数/规则，避免一次同时改很多因素导致不可解释。

## Decision Rules

- 个体交互和空间局部规则主导：考虑 `ALGO_CELLULAR_AUTOMATA` 或 agent-based 思路。
- 纯物理状态方程：优先 `ALGO_ODE_DYNAMICS`。
- 只有静态因果图、无动态问题：不要强行系统动力学。

## Validation Design

- 量纲一致性
- 极端条件/退化情形
- 时间步长收敛
- 历史行为复现（若有数据）
- 政策方向与机制一致性

## Outputs

- 因果回路与 stock-flow 定义
- 状态方程、参数与初值
- 情景结果
- 关键反馈机制解释
- 边界与验证结果

## Checks

- 库存守恒关系正确
- 因果方向有依据
- 参数单位一致
- 政策情景可解释
- 数值结论不依赖粗时间步长

## Failure

- 方程层面数值不稳定：转 `NUMERICAL_SUSPECT` 或 `ALGO_ODE_DYNAMICS`
- 微观空间机制不可忽略：转 `ALGO_CELLULAR_AUTOMATA`
- 参数证据不足：转 `ASSUMPTION_WEAK`

## Common Failure Modes

- **因果回路只是相关图**：每条箭头必须有方向机制和时间含义，不能把相关系数图直接当反馈结构。
- **库存和辅助变量混淆**：只有具有积累记忆的量才是 stock；比例、价格、速率通常是辅助变量或 flow。
- **凭直觉造函数**：非线性响应、阈值和延迟需要数据/机制/情景假设支持，并纳入敏感性分析。
- **参数很多但不可辨识**：系统能拟合历史曲线不代表参数可信；必要时冻结弱可辨识参数或只做机制情景。
- **情景一次改多个机制**：会失去因果解释，应保持政策变化可追踪。

## Numerical Contract

记录积分方法、时间步长、仿真区间和初值；对显著非线性或强反馈模型至少做步长减半/替代积分器对照。若出现负库存、无限增长等违反物理/业务边界的行为，优先检查模型结构，不先用截断函数掩盖。

## Handoff

模型定义完成后转 `MODEL_CONTRACT_MISSING`；情景结论需稳健性时转 `RESULT_UNSTABLE`。
