# queueing

## Trigger

- 事件：`ALGO_QUEUEING`。
- 当问题核心是客户/任务/车辆/工件的到达、服务、排队、等待时间、拥堵或服务能力配置时调用。

## Scope

覆盖经典排队模型与离散事件仿真接口。不是所有“拥堵”问题都适合 M/M/1；分布和服务纪律必须来自数据或合理假设。

## Inputs

- 到达时间/到达率
- 服务时间/服务率
- 服务台数量、容量、队列纪律
- 稳态或瞬态目标
- 评价指标（等待、队长、拒绝、利用率、成本等）

## Procedure

1. 明确实体、到达过程、服务机制、队列容量和纪律。
2. 用数据检查到达间隔与服务时间分布；无数据时把 Poisson/指数假设明确标成假设，而不是事实。
3. 先检查稳定性条件（长期到达负荷不能超过服务能力），不满足时应转容量规划或瞬态仿真。
4. 若结构满足经典 M/M/c、M/G/1 等，使用解析公式作为 Baseline；复杂优先级、有限容量、时变到达或网络排队时考虑离散事件仿真。
5. 核对 Little 定律等结构关系；仿真时处理 warm-up、运行长度和重复独立运行。
6. 若需优化服务台数量，把排队模型作为性能评估器，再转优化 Skill 处理成本—服务水平权衡。

## Decision Rules

- 强时变到达：分时段/非齐次模型或仿真。
- 路网拥堵且路径选择是核心：优先 `ALGO_NETWORK_ROUTING`。
- 服务资源配置含整数决策：组合 `ALGO_LINEAR_INTEGER` 或 `ALGO_NONLINEAR_OPT`。

## Validation Design

- Little 定律/解析特例
- 仿真与解析模型交叉验证
- warm-up 与运行长度收敛
- arrival/service 参数敏感性
- 极端负荷边界测试

## Outputs

- 排队系统合同
- 关键性能指标
- 稳定性与边界条件
- 解析/仿真结果及验证
- 容量或策略建议

## Checks

- 到达与服务假设明确
- 稳态公式仅在稳定条件下使用
- 仿真有重复/区间而非单次随机数
- 等待/队长/利用率单位一致
- 优化建议没有忽略服务水平约束

## Failure

- 稳态不存在：转瞬态仿真或容量优化
- 路由选择主导：转 `ALGO_NETWORK_ROUTING`
- 随机仿真误差过大：转 `ALGO_STOCHASTIC_SIM`

## Common Failure Modes

- **看到平均到达率就套 M/M/1**：Poisson 到达和指数服务是分布假设，不是“有排队”就自动成立。
- **忽略峰谷时段**：全天平均负荷可能掩盖短时超载；需要分时段或非齐次到达率。
- **忽略有限容量/弃队/优先级**：这些机制会改变等待和吞吐，不能用无限 FIFO 队列近似后不说明。
- **仿真初始空系统偏差**：稳态指标应考虑 warm-up；瞬态问题则应保留真实初始状态。
- **只报告平均等待**：高服务风险场景还需分位数、超时概率或 SLA 违约率。

## Optimization Coupling

若题目要求“开几个窗口/配多少资源”，排队 Skill 负责把给定资源配置映射为性能指标；整数资源选择交给优化 Skill。不要在一个黑箱公式里同时隐藏排队假设和决策变量。

## Handoff

需要资源配置时转优化算法；模型冻结前转 `MODEL_CONTRACT_MISSING`。
