# multi-criteria-evaluation

## Trigger

- 事件：`ALGO_MULTI_CRITERIA`。
- 通常由 `model-selection` 在识别问题结构后路由；用户直接点名该算法族时也可调用。
- 本 Skill 只决定该算法族内的技术路线，不决定比赛阶段、时间预算、是否冻结或提交。

## Scope

用于多个指标共同评价方案/对象的任务。核心是指标方向、尺度、权重来源和排序稳健性，而不是套一个综合评分公式。

## Inputs

- 评价对象与指标矩阵
- 指标正/负向及单位
- 权重来源或决策偏好
- 是否需要排名、分级或方案选择
- 指标相关性和缺失情况

## Procedure

1. 先检查指标是否真正对应评价目标，删除定义重复或逻辑包含的指标需有依据。明确效益型/成本型/区间型等方向。
2. 建立最简单可解释 Baseline，例如等权归一化综合指标，作为后续复杂权重方法的比较基线。
3. 归一化方法要与指标含义相容，记录零值、极端值和区间指标处理；不要在不同方法间混用尺度而不说明。
4. 权重分为主观、客观和混合来源。AHP 需一致性检查；熵权反映离散程度，不等于“真实重要性”；PCA 权重反映方差结构。
5. TOPSIS 等距离法明确理想解构造和距离度量，贴近度是相对排序量，不解释为成功概率或百分制成绩。
6. 对权重与归一化方案做敏感性/排名稳定性分析，特别关注前几名是否容易翻转。
7. 若指标强相关，考虑降维、分层指标或重复信息修正；最终解释综合分时回到关键原始指标。

## Decision Rules

- 权重本质上表达偏好或信息结构；没有依据时，优先做等权基线+敏感性，而不是制造“精确权重”。
- 熵权偏好波动大的指标，AHP 表达专家判断，PCA 表达协方差结构；三者含义不同，不能只因排名接近就说“相互验证”。
- 对区间最优指标，先构造与目标距离/效用相关的方向化函数，避免粗暴当正向指标。
- 排名任务若只关心前 k 名，应重点分析 top-k 稳定性，而不是只报告全体 Spearman。

## Validation Design

1. 用等权结果作为 baseline。
2. 对合理权重区间做扰动，记录名次翻转点。
3. 在存在合理替代归一化方案时做对照，确认排序不是尺度处理产物。
4. 对高相关指标做去重/分组后重算，观察重复信息影响。
5. 把最终综合分分解回关键指标贡献，确保结论可解释。

## Outputs

- 指标定义/方向/单位表
- 归一化与权重依据
- Baseline 和候选评价法
- 综合排序/分级结果
- 权重与方法敏感性、排名稳定性

## Checks

- 指标方向无反转
- 权重来源被准确解释
- TOPSIS 贴近度不被写成百分比概率
- 排序对合理权重变化不过度脆弱或已说明
- 原始指标与最终结论能对应

## Failure

- 权重无法合理给出：优先展示多方案敏感性而非编造权重
- 评价任务实际要求预测未来：转 `ALGO_SUPERVISED_LEARNING` 或 `ALGO_TIME_SERIES`
- 排名高度不稳定：转 `RESULT_UNSTABLE`

## Handoff

模型合同冻结后转 `MODEL_CONTRACT_MISSING`，结论解释转 `RESULT_NEEDS_INTERPRETATION`。

统一回执：`status / inputs_used / outputs_written / key_findings / risks / qa_status / handoff`。算法 Skill 可以建议下一事件，但不能替 Coach 做阶段或资源决策。
