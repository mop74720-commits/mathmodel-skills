# game-theory

## Trigger

- 事件：`ALGO_GAME_THEORY`。
- 当多个主体的最优决策相互依赖，存在竞争、合作、定价、竞标、资源争夺或策略互动时调用。

## Scope

覆盖静态/动态、合作/非合作的基本博弈建模思路。若本质是单一中央决策者的优化，不应强行使用博弈论。

## Inputs

- 参与者及其可控决策
- 策略空间
- 收益/成本函数
- 信息结构和行动顺序
- 合作、承诺或联盟可能性
- 可验证的行为/机制事实

## Procedure

1. 先判断是否真的存在多个自主决策主体；若所有变量由一个中央规划者决定，转优化模型。
2. 明确每个主体的策略、约束与收益，收益函数不能只为“凑博弈”而虚构。
3. 明确信息完全/不完全、同时/序贯、一次/重复等结构；这些会决定均衡概念。
4. 构造最简单可解释的博弈 Baseline，求 Nash、Stackelberg 或合作解等与结构匹配的解。
5. 检查均衡存在性、唯一性或多均衡问题；多均衡时必须给选择机制或情景分析。
6. 对关键收益参数、理性假设和信息假设做敏感性；不要把均衡当真实行为必然发生。
7. 若需要社会最优比较，增加 centralized optimum 作为 benchmark，分析效率损失或协调收益。

## Decision Rules

- 单一中央目标：优先优化 Skill。
- 主从关系明确：考虑 Stackelberg。
- 联盟分配核心：考虑合作博弈/Shapley 等，但要说明公理含义。
- 行为明显非理性且有数据：需要行为模型，不宜只用完全理性均衡。

## Validation Design

- 最优反应条件回代
- 均衡稳定性/多均衡检查
- 参数敏感性
- centralized benchmark 对比
- 历史/模拟行为一致性（若有）

## Outputs

- 玩家/策略/收益/信息合同
- 均衡概念与求解
- benchmark 与效率比较
- 参数敏感性和行为边界

## Checks

- 玩家确实有自主决策权
- 收益函数有题面/机制依据
- 均衡概念与行动顺序匹配
- 不把均衡预测写成必然事实
- 多均衡已处理或明确说明

## Failure

- 实际是中央优化：转 `ALGO_LINEAR_INTEGER` 或 `ALGO_NONLINEAR_OPT`
- 收益函数无依据：转 `ASSUMPTION_WEAK`
- 均衡对参数高度敏感：转 `RESULT_UNSTABLE`

## Common Failure Modes

- **把中央优化硬拆成多个玩家**：若所有决策本来由同一主体控制，引入博弈只会增加假设。
- **收益函数缺乏行为意义**：收益不仅是目标函数换个名字，还要反映各主体真正偏好、成本和约束。
- **忽略信息结构**：同时行动、先后行动、完全信息和不完全信息对应不同解概念。
- **多均衡只报一个**：若有多个均衡，数值求解器找到其中一个并不构成唯一预测。
- **把理性均衡当现实必然**：均衡是模型条件下的策略稳定点，应与数据、制度或情景解释结合。

## Comparative Benchmarks

尽量提供两个参照：一是各主体独立决策下的均衡，二是中央协调/社会最优。两者差异可以解释协调价值、价格机制或效率损失。合作博弈分配结果则要说明所用公平性公理，不把 Shapley 值等方法写成唯一公平标准。

## Handoff

模型定义稳定后转 `MODEL_CONTRACT_MISSING`；若需要数值优化求均衡，组合适当优化 Skill。
