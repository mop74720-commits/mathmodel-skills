# efficiency-analysis

## Trigger

- 事件：`ALGO_EFFICIENCY_ANALYSIS`。
- 当对象具有多个投入与多个产出，目标是相对效率、前沿或改进空间，而非单纯排序时调用。

## Scope

主要覆盖 DEA/效率前沿类方法。若任务只是多指标综合排名，应转 `ALGO_MULTI_CRITERIA`。

## Inputs

- DMU 定义与样本数
- 投入/产出变量、方向和单位
- 规模报酬假设
- 是否关注投入导向/产出导向
- 零值、负值与异常值情况

## Procedure

1. 验证 DMU 同质性：对象应处于相似任务和技术环境，否则相对效率没有可比意义。
2. 明确每个指标为何是投入或产出，避免把成本/资源与结果方向弄反。
3. 建立简单描述性 Baseline，先观察规模效应和极端点。
4. 根据问题选择 CCR/CRS、BCC/VRS、投入或产出导向；选择必须由实际管理语义决定。
5. 检查样本量相对指标维度是否过小；自由权重过多会导致大量对象“效率=1”。
6. 求解后报告效率值、参考集/slack、规模效率等真正有解释价值的信息，不只给排名。
7. 做异常 DMU、指标选择和模型假设敏感性；必要时考虑超效率、交叉效率或 bootstrap，但不把复杂扩展当默认。

## Decision Rules

- 只是“谁最好”的综合排序：优先 `ALGO_MULTI_CRITERIA`。
- 有明确生产函数/成本函数：可考虑计量效率或优化模型，而不是强套 DEA。
- 指标含大量负值且无合理变换：先重新定义指标，不直接套标准 DEA。

## Validation Design

- 指标删减/替换后的效率稳定性
- 极端 DMU 去除敏感性
- CRS vs VRS 对照
- 投入/产出方向合理性复核
- slack 与实际改进方向的一致性

## Outputs

- DMU 与投入/产出合同
- DEA 规格和选择依据
- 效率、参考集和 slack
- 稳健性结果
- 可操作的改进解释

## Checks

- DMU 具有基本同质性
- 投入/产出方向无误
- 没把 DEA 效率值解释成绝对概率/分数
- 维度与样本规模风险已说明
- 效率结论可回到原始投入产出解释

## Failure

- DMU 不可比：返回 `MODEL_UNCERTAIN`
- 评价本质是多指标排序：转 `ALGO_MULTI_CRITERIA`
- 结果对少数异常点极敏感：转 `RESULT_UNSTABLE`

## Common Failure Modes

- **把 DEA 当作普通排名**：DEA 衡量相对技术效率，效率为 1 只表示位于当前样本前沿，不等于“综合得分满分”。
- **投入产出指标过多**：维度过高会让太多 DMU 位于前沿，失去区分力。先审查指标逻辑重复，再考虑扩展模型。
- **异质对象混在一起**：地区、机构或企业若承担不同任务、技术约束明显不同，统一前沿可能没有意义。
- **异常点支配前沿**：极端 DMU 会改变大量对象的参考集，必须做删除/稳健性测试。
- **直接使用负值**：标准径向 DEA 对非负性有要求；若数据有负值，应重新定义变量或选择适用扩展，不做任意常数平移后装作无影响。

## Interpretation Contract

论文解释至少区分纯技术效率、规模效率（若计算）、slack/目标改进量与参考 DMU。只有当题目确实要求资源改进建议时，才把 slack 转译成管理含义，并保持单位。

## Handoff

完成规格后转 `MODEL_CONTRACT_MISSING`；若要与其他评价模型比较，转 `MODELS_NEED_COMPARISON`。
