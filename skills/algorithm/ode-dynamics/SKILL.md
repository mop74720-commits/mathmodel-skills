# ode-dynamics

## Trigger

- 事件：`ALGO_ODE_DYNAMICS`。
- 通常由 `model-selection` 在识别问题结构后路由；用户直接点名该算法族时也可调用。
- 本 Skill 只决定该算法族内的技术路线，不决定比赛阶段、时间预算、是否冻结或提交。

## Scope

当状态随时间连续演化，模型由 ODE/状态方程描述时使用。重点是单位、初值、刚性、守恒和参数可辨识性。

## Inputs

- 状态变量与 ODE 方程
- 参数单位与范围
- 初始条件、输入/控制
- 观测量和采样时间（若拟合）
- 守恒律/物理边界

## Procedure

1. 逐项做量纲检查，确认状态导数单位正确；列出初值和外部输入的定义域。
2. 建立最简动力学 Baseline，并识别是否可能刚性、事件触发、不连续输入或多时间尺度。
3. 选择积分器时按结构而非习惯：非刚性可显式高阶方法，刚性优先 Radau/BDF 等；事件需显式 event function。
4. 进行步长/容差收敛检查，至少观察关键结论是否随更严格容差稳定；不要仅看 solver 成功退出。
5. 若系统有质量/能量/概率守恒，计算结构残差；含耗散时检查守恒律应如何修改。
6. 参数识别时区分可辨识性和拟合优度。用 profile、灵敏度、置信区间或多初值检查参数是否唯一/稳定。
7. 对实验数据拟合时将观测模型与状态模型分开，避免把测量噪声直接塞进动力学方程而无解释。

## Decision Rules

- 先识别守恒、耗散、驱动和外部输入，不把所有时间变化都塞进经验项。
- 若特征时间尺度相差几个数量级，优先怀疑 stiffness；不要单纯把显式步长无限缩小。
- 状态变量不可直接观测时，要区分状态估计与参数估计；观测函数是模型合同的一部分。
- 参数多且高度相关时，先做可辨识性分析，避免得到“拟合很好但参数无意义”的结果。

## Validation Design

1. 用简化极限（某参数→0、无外力、无耗散）检查模型退化是否符合理论。
2. 比较不同容差/积分器下关键端点、峰值、周期等统计量。
3. 计算守恒量或功率平衡残差随时间的最大/累计误差。
4. 对参数拟合使用多初值或 profile，确认是否存在等价参数组合。
5. 若数据有噪声，检查残差时间相关性，避免系统性动力学缺失被当随机噪声。

## Outputs

- ODE/状态空间合同
- 积分器与容差选择依据
- 收敛和守恒/结构残差
- 参数识别结果及可辨识性说明
- 关键轨迹与物理解释

## Checks

- 单位与初值完整
- 刚性系统未盲用不适合的显式步进
- 容差收紧后结论稳定或已标注不稳定
- 守恒/耗散规律与方程一致
- 参数拟合不把相关参数误当唯一识别

## Failure

- 数值发散：转 `SOLVER_FAILED`/`NUMERICAL_SUSPECT`
- 空间效应不可忽略：转 `ALGO_PDE_DYNAMICS`
- 参数不可辨识：返回 `ASSUMPTION_WEAK` 或改进观测设计

## Handoff

模型冻结转 `MODEL_CONTRACT_MISSING`；数值验证转 `NUMERICAL_SUSPECT`。

统一回执：`status / inputs_used / outputs_written / key_findings / risks / qa_status / handoff`。算法 Skill 可以建议下一事件，但不能替 Coach 做阶段或资源决策。
