# domain-context

## Trigger

- 事件：`DOMAIN_CONTEXT_NEEDED`。
- 当赛题属于医学/生物、生态/环境、物流/供应链、制造、能源、金融、社会/人口、交通、农业/水利/气象等领域，且领域机制会影响变量、约束、评价或验证方式时调用。
- 不负责替代模型选择；输出应回流到 `MODEL_UNCERTAIN`、`ASSUMPTION_WEAK` 或 `MODEL_CONTRACT_MISSING`。

## Scope

把“领域事实”变成建模可用约束。重点不是列专业名词，而是识别哪些领域特性会改变数据处理、目标函数、约束、评估指标或模型失效边界。

## Inputs

- 题面与问题合同
- 数据字段、单位、时间/空间范围
- 已知领域背景与题目给定机制
- 候选模型或现有假设（如有）
- 可核验的官方资料/领域文献（若任务需要外部事实）

## Procedure

1. 识别领域与决策语境，优先使用题面事实；外部知识只补题面未说明但确实影响建模的机制。
2. 建立“领域机制 → 建模影响”表，至少覆盖：数据生成过程、关键约束、评价口径、常见偏差、不可忽略的时空/因果结构。
3. 按领域检查高风险陷阱：
   - 医学/公共卫生：删失、重复测量、类别不平衡、选择偏差、临床意义≠统计显著；
   - 生态/环境：季节性、空间自相关、阈值/滞后、尺度效应；
   - 物流/交通：容量、时间窗、方向性、拥堵、时变路网、服务水平；
   - 制造：工序前后关系、资源互斥、切换/换产成本、设备可用性；
   - 能源：供需平衡、峰谷、储能状态、耦合约束、可靠性；
   - 金融：厚尾、异方差、前视偏差、交易成本、风险约束；
   - 社会/人口：异质性、网络效应、政策干预、聚合偏差；
   - 农业/水利/气象：季节、空间、资源约束、极端事件和物理边界。
4. 对每个候选模型做“领域适用性反证”：找出一个该模型可能给出数学可行但领域荒谬结果的场景，并检查是否已有约束拦截。
5. 明确哪些评价指标是领域真正关心的，区分统计指标、工程指标和决策指标；必要时建议多指标而非单一精度。
6. 将领域事实写回假设、变量、目标、约束和验证设计；不新增无证据的“常识假设”。

## Outputs

- 领域机制—建模影响表
- 领域特有数据风险清单
- 必须加入/核查的约束与评价指标
- 候选模型的领域失效场景
- 建议回写到问题合同/假设/模型合同的条目

## Checks

- 每条领域知识都能说明其具体建模影响
- 未把题面未提供的领域常识偷偷当事实
- 评价指标与题目决策目标一致
- 已识别“数学可行但领域不可接受”的结果
- 外部领域事实需要引用时可追溯

## Failure

- 领域事实不足且会改变模型结构：返回 `PROBLEM_AMBIGUOUS` 或请求可核验资料
- 领域知识暴露关键假设不成立：转 `ASSUMPTION_WEAK`
- 已明确领域约束但模型族尚未确定：转 `MODEL_UNCERTAIN`

## Handoff

优先 handoff 到 `MODEL_UNCERTAIN`、`ASSUMPTION_WEAK` 或 `MODEL_CONTRACT_MISSING`。领域 Skill 不决定比赛优先级，也不把某个行业惯例升级成官方规则。
