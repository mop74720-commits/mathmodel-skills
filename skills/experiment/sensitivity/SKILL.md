# sensitivity

## Trigger

- 事件：`NEED_SENSITIVITY`。
- 用户明确点名本能力时也可直接调用。
- 本 Skill 只解决局部问题；比赛阶段、时间预算、是否放弃某题仍由 Coach 决定。

## Scope

用于参数影响分析，不应机械地对所有参数做相同 ±10% 扰动。扰动范围必须来自题面、数据分布、物理允许区间或合理工程范围。

## Inputs

- 冻结模型合同
- 基准参数与 Final/Baseline
- 参数合法范围或数据依据
- 关键输出/决策指标

## Procedure

1. 先筛选真正需要分析的参数：题面不确定参数、估计参数、关键阈值、高影响假设；固定常量或无不确定性的输入无需为了数量强行分析。
2. 根据参数性质选择设计：连续且局部平滑可用局部扰动/弹性；强非线性或交互明显可用网格、采样或全局敏感性；离散/整数参数用邻近可行值或情景比较。
3. 扰动范围必须记录来源。百分比扰动只是可选方法，不能作为统一默认。
4. 每次扰动重新检查约束与可行域；混合整数问题不能对整数结果做线性微分后宣称“灵敏度”。
5. 报告输出变化和结论变化两层：数值变化大但策略/排名不变，与数值变化小但跨过决策阈值，含义不同。
6. 识别参数交互；若单因素结论明显依赖另一个参数，增加少量二维/联合实验。
7. 把高敏感参数送入稳健性或误差控制计划，而不是只画一张折线图。

## Outputs

- 敏感性实验设计与来源
- 参数-输出响应表/图
- 高敏感参数和阈值
- 对最终结论稳定性的说明

## Checks

- 扰动始终位于合法域
- 离散与连续参数使用合适方法
- 结果解释区分数值敏感与决策敏感
- 没有把局部结论外推到整个参数空间

## Failure

- 对合理扰动结论频繁翻转：转 `RESULT_UNSTABLE`
- 参数范围本身无依据：回 `ASSUMPTION_WEAK`
- 敏感性只因数值设置引起：转 `NUMERICAL_SUSPECT`

## Handoff

返回敏感参数及建议的稳健性/验证事件。

统一回执字段：`status / inputs_used / outputs_written / key_findings / risks / qa_status / handoff`。Skill 可以建议下一个事件，但不能自行切换比赛阶段。
