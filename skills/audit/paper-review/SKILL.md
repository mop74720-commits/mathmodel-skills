# paper-review

## Trigger

- 事件：`PAPER_NEEDS_ATTACK`。
- 用户明确点名本能力时也可直接调用。
- 本 Skill 只解决局部问题；比赛阶段、时间预算、是否放弃某题仍由 Coach 决定。

## Scope

这是语义审稿，不替代格式脚本。reviewer 默认只读，输出证据化问题而不是直接重写全文。

## Inputs

- 论文正文/PDF 或可渲染稿
- 问题合同
- 模型合同
- Final Run/Claim-Evidence Map
- 图表与参考文献

## Procedure

1. 先检查答题完整性：摘要、正文和结论是否覆盖全部子问题，答案是否能被快速定位。
2. 审数学链：公式是否定义充分、推导有没有跳步、符号/单位是否冲突、模型条件是否在使用前声明。
3. 审证据链：关键数字、优越性、显著性、鲁棒性、创新性是否有直接结果或文献支持。
4. 审一致性：摘要/正文/表图/附录代码中的参数、数值、单位、模型名称是否互相冲突。
5. 审图表：是否真正支持 claim，是否重复、误导、缺单位、正文不引用或图注不足。
6. 审写作：背景是否过长、问题重述与分析是否重复、算法百科是否挤占结果、段落是否有明确论点。
7. 审风险表述：避免“完全准确、证明最优、显著提升”等超出证据的结论；检查可能的模板化/AI 痕迹只作为可读性和原创性风险，不用主观检测器当定罪证据。
8. 按 P0/P1/P2 排序问题，并指出页/节/公式/图表位置。

## Outputs

- 评阅问题矩阵
- P0/P1/P2 分级
- 必须修复与可选增强清单

## Checks

- 问题都有精确位置和理由
- 不使用虚构官方评分表打“总分”
- 不因风格偏好判数学错误
- 关键事实与 Final/合同交叉核对

## Failure

- P0/P1：FAIL 并回对应 modeling/coding/writing
- 缺权威规则：最终格式问题留给 `PRE_SUBMISSION` 核验
- 仅 P2：WARN，可由 Coach 决定是否继续优化

## Handoff

返回只读审稿回执；修改后需要针对受影响范围复审。

统一回执字段：`status / inputs_used / outputs_written / key_findings / risks / qa_status / handoff`。Skill 可以建议下一个事件，但不能自行切换比赛阶段。
