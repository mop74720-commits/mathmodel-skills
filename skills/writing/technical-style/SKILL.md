# technical-style

## Trigger

- 事件：`WRITING_STYLE_WEAK`。
- 当正文逻辑基本正确，但存在模板句堆叠、结果只报数字、模型选择无理由、评价空泛或 AI 式重复表达时调用。

## Scope

只改表达与论证密度，不改变模型、数据、数值结论或引用事实。目标不是“规避检测器”，而是让语言与真实研究推理一致。

## Inputs

- 待修改段落/章节
- 对应 model contract、结果和图表
- 论文术语/符号表
- 需要保留的事实与数字

## Procedure

1. 标记四类低质量表达：题目复述、步骤流水账、无解释数字、无证据评价。
2. 对模型选择句补齐“为什么适合本题结构 / 为什么不采用更简单或更复杂替代”，但不得编造比较实验。
3. 对关键结果采用“结果 → 比较 → 原因/机制 → 决策或工程含义 → 限制”的最小证据链；不是每个数字都机械套五段式。
4. 删除重复的“针对问题一/首先/其次/最后”等模板连接词，仅在逻辑需要时保留。
5. 优先使用准确数学对象和变量名，避免用空泛形容词替代公式或数据。
6. 模型优点必须对应实际结构或验证证据；缺点必须真实并说明影响范围。
7. 图表附近说明“图证明什么”，避免重复朗读坐标轴。
8. 完成后逐项核对所有数字、单位、符号和因果词，确保风格修改没有改变事实含义。

9. 若低质量来源不是句式而是“Repo/审计内容直接进入正文”或结构膨胀，不在本 Skill 逐句润色，转 `PAPER_SYNTHESIS_NEEDED` / `PAPER_TOO_BLOATED`。

## Outputs

- 修订后的技术文本
- 被删除的空泛/模板化表达类型说明（可选）
- 若发现证据缺失，列出缺口而不是补写虚构依据

## Checks

- 关键模型选择有理由
- 关键数值有解释但不过度因果化
- 无空泛“精度高、效果好、创新性强”而缺证据
- 风格修改未改变数字、单位、符号和结论边界
- 不把“降低 AI 痕迹”当成论文质量目标本身

## Failure

- 需要真实结果才能改写：转 `CLAIM_UNSUPPORTED`
- 原文数学逻辑有问题：转 `PAPER_NEEDS_ATTACK` 或 `MODEL_NEEDS_REVIEW`
- 摘要结构本身有问题：转 `ABSTRACT_NEEDED`

## Handoff

文本修订完成后可转 `PAPER_NEEDS_ATTACK` 做独立审稿。该 Skill 不负责制造“人类写作痕迹”，只负责技术表达质量。
