# numerical-check

## Trigger

- 事件：`NUMERICAL_SUSPECT`。
- 用户明确点名本能力时也可直接调用。
- 本 Skill 只解决局部问题；比赛阶段、时间预算、是否放弃某题仍由 Coach 决定。

## Scope

面向“代码能跑但数值可信度不明确”的情况。它不要求所有题都做昂贵的高精度研究，只检查会影响核心结论的数值风险。

## Inputs

- 模型合同
- 当前结果/Final 候选
- 求解器配置
- 可运行代码
- 已知解析/物理约束（如有）

## Procedure

1. 先列核心数值量和可接受的误差定义：目标值、状态轨迹、约束残差、守恒量、排名/策略等。
2. 做离散/容差收敛：按问题选择网格加密、时间步减半、积分容差收紧、优化容差变化；观察关键结论是否收敛，而不是只看程序是否完成。
3. 检查尺度与条件：变量/约束跨多个数量级时评估缩放、条件数或残差；必要时做等价重参数化。
4. 随机算法检查多种 seed 的分布、最好/中位/最差与稳定性；不能用“固定一个 seed”代替稳定性分析。
5. 检查结构残差：优化可行性、ODE/PDE 方程残差、守恒/单调性、边界条件、概率和为 1、流量守恒等适用不变量。
6. 可行时使用独立实现、不同 solver 或退化/解析极限进行交叉验证，但不为了形式强制双实现。
7. 定义“数值误差是否足以改变论文结论”，若不会改变则记录为非阻断误差；若会改变则 FAIL。

## Outputs

- 数值可信度报告
- 收敛/稳定性表或图
- 关键残差/不变量检查
- 推荐精度配置

## Checks

- 至少一个与模型结构相关的正确性检查
- 精度调整后关键结论趋势明确
- 没有把 solver 内部误差估计当作全部验证
- 随机误差和离散误差不混为一谈

## Failure

- 结果随精度设置显著漂移：返回 FAIL，继续 numerical/solver 调查
- 结果主要受随机场景影响：转 `RESULT_UNSTABLE`
- 数值通过后需冻结 Final：转 `FINAL_RESULT_NEEDS_REVIEW`

## Handoff

输出“可信/有条件可信/不可信”及证据；最终采用哪档精度由 Coach 与计算预算共同决定。

统一回执字段：`status / inputs_used / outputs_written / key_findings / risks / qa_status / handoff`。Skill 可以建议下一个事件，但不能自行切换比赛阶段。
