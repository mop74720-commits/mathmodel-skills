# ambiguity-resolution

## Trigger

- 事件：`PROBLEM_AMBIGUOUS`。
- 用户明确点名本能力时也可直接调用。
- 本 Skill 只解决局部问题；比赛阶段、时间预算、是否放弃某题仍由 Coach 决定。

## Scope

用于会实质改变变量、约束、数据处理或最终答案的题意歧义。措辞小差异但不改变计算结果时，不需要启动本 Skill。

## Inputs

- 歧义原文位置
- 问题合同
- 相关附件/数据事实
- 后续子问题要求

## Procedure

1. 把歧义写成至少两个可执行解释 A/B（必要时更多），每个解释必须明确“如果这样理解，变量/约束/输出会怎样变化”。
2. 逐一做四类检查：原文语义一致性、量纲/物理一致性、与后续问题递进性、是否让题面给出的关键条件产生合理边际作用。
3. 用最小计算或边界案例测试解释：若某解释导致后续问题退化、关键参数永远不起作用、明显无解或与样例矛盾，降低其可信度。
4. 优先选择能够同时解释最多题面事实且引入最少额外假设的解释；不要因为某解释更容易算就选择它。
5. 记录被否决解释及证据，避免后续人员重复争论同一问题。
6. 若无法唯一裁决，保留主解释 + 备解释，并指出哪些结果对解释敏感；由 Coach 决定是否双轨计算。

## Outputs

- 歧义决议表：解释、支持证据、反证、影响范围、结论
- 选定解释及置信说明
- 必要时的备解释和回滚条件

## Checks

- 结论引用具体题面/数据证据而非“通常这样理解”
- 没有用结果好看与否作为主要裁决标准
- 关键歧义对后续模型影响被显式记录

## Failure

- 所有解释都与题面冲突：返回 `PROBLEM_UNCLEAR` 重新检查是否漏读条件
- 无法裁决且差异会影响结论：返回 WARN 并建议 Coach 保留双轨
- 歧义解决后需要补充假设：转 `ASSUMPTION_WEAK`

## Handoff

通常推荐回到 `PROBLEM_UNCLEAR` 更新问题合同，或继续 `MODEL_UNCERTAIN`。

统一回执字段：`status / inputs_used / outputs_written / key_findings / risks / qa_status / handoff`。Skill 可以建议下一个事件，但不能自行切换比赛阶段。
