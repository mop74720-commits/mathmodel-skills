# flowchart

## Trigger

- 事件：`FLOWCHART_NEEDED`。
- 用户明确点名本能力时也可直接调用。
- 本 Skill 只解决局部问题；比赛阶段、时间预算、是否放弃某题仍由 Coach 决定。

## Scope

适用于存在分支、循环、反馈、数据加工链或多角色交互的流程。线性 3 步以内且无需结构表达时，通常正文列表更清楚。

## Inputs

- 要表达的流程/算法
- 关键输入输出
- 分支条件/循环条件
- 论文版面尺寸

## Procedure

1. 先选择流程图类型：算法控制流、数据流、决策树、实验闭环或系统架构；不同语义不要混在一张图里。
2. 提取最少节点：输入、关键处理、决策、循环、输出；删除论文正文已经详细解释且不影响流程理解的细节。
3. 对每个判断节点使用可判定条件，并确保每个分支都有去向；循环必须标明终止条件。
4. 保持单一主阅读方向，避免大量交叉线；必要时拆成主流程 + 子流程。
5. 节点命名用动宾短语或状态，不在方框里塞整段说明。
6. 检查图是否能独立回答“输入是什么、在哪做判断、何时结束、输出是什么”。
7. 与代码/模型合同对照，确认图中的顺序和条件没有为了美观被简化到错误。

## Outputs

- 流程图语义合同
- 节点/边清单
- 可直接绘制的结构说明或源文件（若工具支持）

## Checks

- 分支与循环完整
- 没有孤立节点
- 图中术语与论文/代码一致
- 在论文预计尺寸下仍可读

## Failure

- 实际是数据关系图：转 `FIGURE_NEEDED`
- 图与实现不一致：返回 coding/modeling 修正
- 生成后视觉拥挤：转 `FIGURE_WEAK`

## Handoff

返回图结构和需要核对的代码/论文位置。

统一回执字段：`status / inputs_used / outputs_written / key_findings / risks / qa_status / handoff`。Skill 可以建议下一个事件，但不能自行切换比赛阶段。
